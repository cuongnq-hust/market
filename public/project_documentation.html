1. Tổng Quan Dự Án & Bài Toán Nghiệp Vụ

Pass Đồ Gần Nhà ra đời nhằm giải quyết triệt để sự đứt gãy thông tin giữa người dọn nhà/dọn phòng trọ cần thanh lý đồ cũ cồng kềnh gấp và vựa thu mua phế liệu/người cần mua đồ giá rẻ trong bán kính gần (1km - 20km).

🎯 Bài toán thực tế

Đồ cũ như bàn ghế, máy giặt, quạt, tủ lạnh, sách cũ khi dọn nhà vận chuyển xa rất tốn phí. Đăng lên sàn TMĐT hoặc nhóm Facebook thì quá xa và mất thời gian đóng gói ship.

💡 Giải pháp Hyperlocal

Bản đồ số định vị thời gian thực, quét trong bán kính lân cận từ 1km đến 20km. Người mua có thể đi bộ hoặc chạy xe máy 5 phút qua xem đồ và chở về ngay.

⚡ Tối giản rào cản

Không bắt buộc người dùng đăng ký tài khoản rườm rà. Định danh ẩn danh qua Device Session; kết nối trực tiếp 1 chạm qua Zalo và Gọi thoại.

🛡️ Tự động điều tiết

Người bán cá nhân bán xong chỉ cần ấn "Đã bán" -> vị trí tự động ẩn khỏi bản đồ để tránh bị làm phiền. Tin xấu bị 3 người báo cáo sẽ tự động bị ẩn khỏi cộng đồng.

4. Hàm Tính Bán Kính Không Gian Địa Lý (GIS Function)

Để tối ưu hiệu năng và độ chính xác tính khoảng cách theo độ cong Trái Đất (Great-Circle Distance), hệ thống cài đặt hàm công thức Haversine trực tiếp bằng ngôn ngữ PL/pgSQL:

-- 1. Hàm tính khoảng cách chính xác theo km giữa 2 tọa độ GPS
CREATE OR REPLACE FUNCTION calculate_distance_km(
    lat1 DOUBLE PRECISION, lon1 DOUBLE PRECISION,
    lat2 DOUBLE PRECISION, lon2 DOUBLE PRECISION
) RETURNS DOUBLE PRECISION AS $$
DECLARE
    r DOUBLE PRECISION := 6371.0; -- Bán kính Trái Đất trung bình (km)
    dlat DOUBLE PRECISION := radians(lat2 - lat1);
    dlon DOUBLE PRECISION := radians(lon2 - lon1);
    a DOUBLE PRECISION;
    c DOUBLE PRECISION;
BEGIN
    a := sin(dlat / 2.0)^2 + cos(radians(lat1)) * cos(radians(lat2)) * sin(dlon / 2.0)^2;
    c := 2.0 * atan2(sqrt(a), sqrt(1.0 - a));
    RETURN ROUND((r * c)::numeric, 2);
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 2. Hàm quét tìm điểm bán trong bán kính radius_km và sắp xếp tăng dần
CREATE OR REPLACE FUNCTION get_nearby_sellers(
    user_lat DOUBLE PRECISION, user_lon DOUBLE PRECISION, radius_km DOUBLE PRECISION
)
RETURNS TABLE (
    user_id UUID, shop_name VARCHAR, seller_type VARCHAR,
    address TEXT, latitude DOUBLE PRECISION, longitude DOUBLE PRECISION,
    categories TEXT[], open_time VARCHAR, close_time VARCHAR,
    is_open_now BOOLEAN, phone VARCHAR, zalo VARCHAR,
    rating NUMERIC, is_verified BOOLEAN, is_sold_out BOOLEAN,
    distance_km DOUBLE PRECISION
) AS $$
BEGIN
    RETURN QUERY
    SELECT s.user_id, s.shop_name, s.seller_type, s.address, s.latitude, s.longitude,
           s.categories, s.open_time, s.close_time, s.is_open_now, s.phone, s.zalo,
           s.rating, s.is_verified, s.is_sold_out,
           calculate_distance_km(user_lat, user_lon, s.latitude, s.longitude) AS distance_km
    FROM public.seller_profiles s
    WHERE s.is_sold_out = false
      AND calculate_distance_km(user_lat, user_lon, s.latitude, s.longitude) <= radius_km
    ORDER BY distance_km ASC;
END;
$$ LANGUAGE plpgsql STABLE;

5. Cấu Hình Đồng Bộ Realtime & Phân Quyền (RLS)

Cơ chế đồng bộ Realtime không cần F5

Khi máy A đăng tin hoặc đánh dấu Đã Bán, máy B sẽ nhận được sự kiện qua kênh WebSocket supabase_realtime trong < 300ms.

Cải tiến UX thông minh: Để tránh trường hợp người dùng đang đọc bài mà trang bị giật hoặc tải lại liên tục khi database có biến động, hệ thống sử dụng thanh thông báo nổi "Có N tin mới đăng · Bấm để xem" (giống cơ chế của Twitter/Threads). Khi người dùng chủ động bấm hoặc lướt lên trên thì tin mới mới trượt vào êm ái. 
-- Kích hoạt Realtime Publication trên Supabase
ALTER PUBLICATION supabase_realtime ADD TABLE public.seller_profiles;
ALTER PUBLICATION supabase_realtime ADD TABLE public.products;
ALTER PUBLICATION supabase_realtime ADD TABLE public.forum_posts;
ALTER PUBLICATION supabase_realtime ADD TABLE public.forum_comments;

-- Phân quyền truy cập công khai cho ứng dụng C2C không cần login
ALTER TABLE public.users DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.seller_profiles DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.products DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.forum_posts DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.forum_comments DISABLE ROW LEVEL SECURITY;

GRANT ALL ON public.users TO anon, authenticated, service_role;
GRANT ALL ON public.seller_profiles TO anon, authenticated, service_role;
GRANT ALL ON public.products TO anon, authenticated, service_role;
GRANT ALL ON public.forum_posts TO anon, authenticated, service_role;
GRANT ALL ON public.forum_comments TO anon, authenticated, service_role;

8. Các Trường Hợp Kiểm Thử Biên & Xử Lý Ngoại Lệ (Edge Cases)

🌐 Mạng chập chờn / Mất kết nối

Service Worker lưu cache-first app shell (HTML, CSS, JS, Icon SVG) giúp giao diện vẫn mở mượt mà tức thì. Khi có mạng trở lại, API REST Supabase tự động cập nhật.

🚫 Xử lý lỗi API REST 400

Cú pháp query Supabase REST được format chặt chẽ, chuỗi URL được encode an toàn tránh lỗi cú pháp or=(status.eq.available,author_id.eq.uuid) khi filter danh sách tin.

🔄 Debounce thao tác liên tục

Thao tác kéo slider bán kính và nhập ô tìm kiếm được tích hợp debounce thời gian trễ 250ms, tránh gửi hàng chục truy vấn dồn dập làm nghẽn kết nối mạng của thiết bị.

📦 Tối ưu Bundle Code-Splitting

Các thư viện nặng (Leaflet, Supabase, Lucide) được chia tách thành các chunk độc lập, không có file JS nào vượt quá 500kB, thời gian nạp trang đầu tiên đạt dưới 1.2s trên mạng di động 4G.
